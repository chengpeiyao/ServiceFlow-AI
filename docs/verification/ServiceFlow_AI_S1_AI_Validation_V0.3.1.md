## 2. S1 最小纵切（不需要先做派工页面）

| 验收 ID | 输入/操作 | 期望结果 |
|---|---|---|
| `S1-01` | 客户 A 合法合同创建故障工单 | `SUBMITTED`；团队、优先级、SLA 版本冻结；原文保存 |
| `S1-02` | 客户 A 使用客户 B 的合同 | 拒绝且不落工单/SLA/审计的成功事件 |
| `S1-03` | 合同过期或服务类型未覆盖 | 创建失败；不降级匹配或生成假 SLA |
| `S1-04` | SLA 绑定从 V1 切换为 V2 | 新工单引用 V2，原工单继续引用 V1 |
| `S1-05` | 客户 B 读取 A 的工单 | 403/404，返回体不包含 A 的敏感字段 |
| `S1-06` | 客户创建时不填写产品和版本 | `reported_product_*` 均为 NULL，后续检索只用通用知识 |
| `S1-07` | 客户在 `SUBMITTED` 补充产品/版本并追加消息 | 原文不变；保存客户申报；ticket.version++；审计保留来源 |
| `S1-08` | 客服人工受理 | 只写 category、受理记录，状态 `TRIAGED`；团队、合同、SLA 不变 |
| `S1-09` | 客服提交服务类型/团队等非法受理字段 | 422，工单不变 |
| `S1-10` | 客户补充与客服受理并发 | 分别验证两种先后顺序：补充先提交则旧版本受理失败；受理先提交则旧版本补充返回冲突。并发竞争只能一个旧版本写入成功，失败请求明确返回 409 |

**输出物：** 可运行 Spring Boot 最小服务、Flyway 建表、种子 SQL、JUnit 5 + Testcontainers 集成测试记录。`S1-01`～`S1-10` 已由真实集成测试验证通过；`S1-10` 拆为两种明确顺序及真实双请求竞争三个场景。后续用例保持待执行。

## 3. S2 前需落实的首次派工与转派断言

| 验收 ID | 组合 | 期望结果 |
|---|---|---|
| `TASK-01` | `TRIAGED + CREATED` 首次派工 | 工单 `ASSIGNED`、任务 `ASSIGNED`、1 条派工历史 |
| `TASK-02` | `ASSIGNED + ASSIGNED` 转派 | 工单保持 `ASSIGNED`，任务保持 `ASSIGNED`，负责人改变、历史追加 |
| `TASK-03` | `IN_PROGRESS + PROCESSING` 转派 | 工单保持 `IN_PROGRESS`；任务回到 `ASSIGNED`；新人必须重新接单和开始 |
| `TASK-04` | 验收拒绝后 `IN_PROGRESS + CREATED` 首次派整改任务 | 工单继续 `IN_PROGRESS`，任务 `ASSIGNED` |
| `TASK-05` | 转派后旧工程师尝试 `completeTask` | 403/404 或在权限仍有效而版本失效时 409，不能更新数据 |
| `TASK-06` | 双主管并发转派 | 一方更新成功，另一方按期望版本返回冲突；不会错乱当前负责人 |
| `TASK-07` | 用相同 `Idempotency-Key` 重放转派 | 不新增第二条派工历史 |

## 4. AI 检索适用性与新旧草稿测试

| 验收 ID | 场景 | 必须通过的条件 |
|---|---|---|
| `AI-KB-01` | 产品/版本完整 | 通用 + 精确匹配版本 + 产品通用知识；排除不兼容版本 |
| `AI-KB-02` | 产品已知、版本未知 | 仅通用 + 该产品 `ALL` 知识；提出版本追问 |
| `AI-KB-03` | 产品未知、版本未知 | 只用 `GENERAL/ALL`；不得用模型猜测过滤 |
| `AI-KB-04` | 无适用知识 | 明确证据不足，追问补充，不生成虚假引用 |
| `AI-KB-05` | 错配版本或引用片段不支持结论 | 标记不适用/交由人工评审，不将推测表述为事实 |
| `AI-DRAFT-01` | 旧 pending 版本 12、新工单版本 13、新 run 观察 13 | 旧草稿 `STALE`，新草稿成为唯一 `PENDING_REVIEW` |
| `AI-DRAFT-02` | 旧 pending 版本一致但过期 | 旧草稿 `EXPIRED`，新草稿可保存 |
| `AI-DRAFT-03` | 旧 pending 未过期且版本一致 | 新 run 为 `SUPERSEDED`；不新增 proposal |
| `AI-DRAFT-04` | 新 run 观察 12、当前工单 13 | 新 run 为 `STALE`；不得将旧建议绑定版本 13 |
| `AI-DRAFT-05` | 无权客服尝试使草稿失效 | 403，原草稿及审计状态不被修改 |
| `AI-DRAFT-06` | 两个 run 并发保存 | 恰好一个 pending，另一个 run `SUPERSEDED` |

## 5. A0/A1/A2 真实模型实验

- **样例：** 20 条开发集、40 条固定检查集，覆盖完整产品版本、仅产品、未知产品、错误申报；同一模板族不要拆入不同集合。
- **冻结：** A1/A2 相同模型、版本、采样参数、输出 Schema、校验器、错误处理；主要区别仅是否附检索证据；A0/A2 相同知识与检索器。
- **记录：** 案例 ID、分组、分类、事实字段正确/错误、必须追问漏问数量、冗余追问数量、引用是否真的支持建议、耗时、Token、估算费用与模型失败类型。
- **安全阈值：** 不允许 AI 输出更新 SLA、合同、团队、优先级的业务写入。模型失败时业务仍可人工受理。
- **禁止提前宣称结果：** 代码与真实模型运行后再填写正确条数/百分比，不把未经运行的用例作为通过证据。
