# S1-AI 实验原始证据

`a0-dev-v0.1` 和 `a0-fixed-v0.1` 是 2026-10-19 最终六类编码运行目录的原样副本；不包含密钥或真实客户数据。目录内 manifest 的构建位置指向可写临时工作副本，经过完整测试后将同一 JAR、源码与资料按 SHA-256 校验交付到项目目录，没有篡改记录中的原始路径。

`completed.json` 表示整批执行完成，`summary.json` 为自动计数；`human-review.jsonl` 中所有人工评分均为空。本归档不是专家验收证据，不能把机械校验计数当作语义正确数。

用于正式对照的基线与独立历史运行分别记录；未归档的新运行暂存在本地忽略目录 `runs`。后续模型实验应使用相同资料哈希；如果修改了资料或 Schema，应显式建立新版本。

`model-preflight-2026-10-19` 记录用户配置完成后的真实调用预检：A1 开发案例首次请求及一次重试均为 429，独立错误诊断返回 `insufficient_quota / credit_balance_exhausted`。归档包含 `probe-A1.json`、`api-diagnostic.json`、`preflight-manifest.json`，只保存脱敏状态、耗时、参数与哈希，不包含密钥、请求认证头或服务端错误正文。

该预检没有生成输出，没有运行 A2 或完整开发/固定检查集，不能混入 A0/A1/A2 的质量对比，也不能记为模型分类错误或零费用。

`ollama-smoke-2026-10-20` 为本机 `qwen3:4b-instruct` 开发案例 `D-01` 的 A1/A2 顺序调用：HTTP 均为 200，但事实校验均未通过。原始 `probe-A1.json`、`probe-A2.json` 仅表示传输/解析结果；`verification.json` 保存校验失败、耗时、用量、JAR 与资料哈希。尚未完成全开发集、固定集或人工评分，不作为模型效果验收证据。详见 [调用验证说明](../../../docs/verification/ServiceFlow_AI_Ollama_Call_Verification_2026-10-20.md)。

`dev-v03-2026-10-20` 是提示词 `s1-ai-intake-v0.3` 的 20 条开发集完整 A0/A1/A2 对照，共 60 条记录。A1 含 1 次超时，A2 含 2 个校验拒绝，均保留在结果中。`environment.json` 记录实际 Ollama 版本和模型 digest，其他 manifest/完成标识及人工评分表沿用统一结构。A0 计数与原冻结基线一致；提示词与校验器版本不同于此前单案例，不能只靠模型名比较。

本轮未调用 A1/A2 固定集，所有人工评分仍为空。原始分类、接受后的分类及漏问等计数需要结合拒绝原因解读，不能挑选成功回答宣传效果。结果与限制见 [完善记录](../../../docs/verification/ServiceFlow_AI_S1_AI_Refinement_2026-10-20.md)。
