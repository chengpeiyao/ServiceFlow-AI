# 开发集标签与事实语义复核

本目录只准备复核材料，不表示已经完成人工评分。原始 dev/fixed/knowledge/Schema 本轮均不修改。

## 标签口径候选

| 字段 | 待确认口径 | 容易混淆的内容 |
|---|---|---|
| symptom | 客户原文中最小且充分的故障现象，保留必要限定 | 根因推断、完整无关背景；更长但正确的短语不应只靠精确匹配判语义错误 |
| errorCode | 明确错误码或报错文字 | MQTT/DNS 等协议名；没有错误提示的否定事实是否纳入，仍待决定 |
| change | 故障前明确发生或明确否认的发布、升级、配置调整 | 故障后的重试、症状、原因推测、单纯版本号 |
| frequency | 明确重复间隔或发生次数/频率 | 发生时间、耗时、持续时长、时间偏移 |
| startTime | 故障开始时间，无法确定时应追问 | 最后正常/心跳时间不必然是开始时间 |
| scope | 明确受影响或未受影响的用户、设备、功能或网络范围 | 查询筛选条件、猜测的影响面 |
| product/version | description 中实际出现的产品/版本表述 | 显式元数据不是原文；冲突信息应单独澄清 |

`dev-label-audit-v1.jsonl` 包含原文、原标注、原数据 SHA-256 和开发者待核查意见。意见是复核候选，不是专家结论。实际复核时复制为新文件，填写 reviewer、decision、notes；需要改标签时填写 proposedGold，但不要覆盖原数据。20 条均保留 PENDING_HUMAN_REVIEW，不能把准备表格说成标签复核完成。

若改变事实定义或必问项，建立独立数据版本，记录旧新差异和审核人，再用同一新版本重新评价 A0/A1/A2/A3；禁止把新标签分数与旧结果直接排名。固定检查集只在口径、Prompt、规则、模型配置冻结后运行。

## 输出语义评分

原有精确引文与严格校验保持不变。运行目录中的 human-review.jsonl 继续用于案例级人工事实、追问和证据评分；A3 的 output 是最终规则/模型组合输出，其他组沿用原始候选。所有组未评分项均为 NULL。

本轮归档还生成 fact-semantic-review.jsonl，逐条保留字段、值、原文引用、机械来源检查结果及待填的 fieldMeaningCorrect、valueMeaningCorrect、reviewer、notes；以 sourceView 区分原始模型和最终输出。原始候选被拒绝时也保留逐事实复核材料，但不能作为可用输出。判断维度：

- 引文正确但归入了错误字段：fieldMeaningCorrect=false，不能靠改引文规则放行。
- 值语义正确但比标注长：人工 valueMeaningCorrect 可以为 true，精确匹配结果仍保留原值。
- 空事实不能自动认为事实提取正确；遗漏在案例级 factsSemanticCorrect 中反映。
- 引用真实不等于支持建议，evidenceSupportsSuggestion 仍须结合原文和完整知识逐案例判断。

逐事实表只作为复核工作底稿，未自动并入汇总，也不代填人工分数。初次人工评分完成后再决定是否需要统一的逐事实汇总功能。
